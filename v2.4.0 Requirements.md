## 1. Scope of v2.4.0

v2.4.0 is a **design-polish increment** on top of a shipped v2.3.0. Two requests, no new object types, no schema migrations, no new top-level surfaces (see §4 — Data model deltas below, which is intentionally empty). All locked decisions from v2.0.0 continue to hold — in particular the whole of `DM-NOT` (no streaks / points / badges / adherence %), the five-tab primary structure (`FR-NAV-1`), and the compass / chosen-direction thesis.

The requirements:

- **`FR-ABOUT-2`** refines the About screen introduced by `FR-ABOUT-1` with an explicit type-treatment plan across the three text rows and the Contact Us link, a proportional-to-viewport rule for `FoxLogo` sizing (currently hard-coded at 108 dp), and a vertical-centering layout so the whole screen sits comfortably in the middle of the viewport and fits without scrolling on default text scale in both portrait and landscape. Refines `FR-ABOUT-1.2` (body content order) and `FR-ABOUT-1.6` (layout / no-scroll rule).
- **`FR-NAV-5`** normalises the chrome palette so **every top-level tab and reference view uses the same rust `RustHeader` treatment** — retiring the cream `LayerHeader` currently rendered on Habits / Directions / Journey, which reads today as if those three views belong to a different app. Refines `FR-NAV-1` chrome.
- **`FR-NAV-6`** makes navigation affordances consistent so **no view is a dead-end**: primary and reference views all carry the bottom nav (`DenBottomNav`) and the hamburger (`FR-NAV-3`), while leaf destinations (Settings, About) carry a single "close" (`×`) affordance that returns to whichever view opened them. Refines `FR-NAV-1` (bottom-nav visibility), `FR-NAV-3` (hamburger placement), and `FR-ABOUT-1.1` (About left-slot affordance).
- **`FR-NAV-7`** normalises the screen-title size across `RustHeader` (all views render the title at `DenType.h1`; the `compact = true` opt-in is retired) and restructures Planning's header so the current date sits in the kicker slot and the "WHAT'S ON THE TABLE" line is removed, freeing vertical room for the "Planning" title at full weight without the header growing overall. Refines `FR-PLAN-1` (Planning header layout) and adjusts About / Settings / Backlog / All Tasks title sizing accordingly.

Nothing here is gamification-adjacent — there is no streak / points / badges / adherence surface anywhere in the refresh (`DM-NOT`, `DEC-2/3/4`).

## 2. Functional requirements

### 2.1 About screen visual design — type, logo size, centering (`FR-ABOUT-2`, refines `FR-ABOUT-1.2` / `FR-ABOUT-1.6`)

*Source: `FR-2026-07-11-a`. Refines `FR-ABOUT-1.2` / `FR-ABOUT-1.6`; introduces `FR-ABOUT-2.*`.*

`FR-ABOUT-1` shipped an About screen whose body content order, `FoxLogo` presence, and Contact Us affordance are all correct — the design decisions the source request now asks us to make are the ones the v2.3.0 requirement deferred to implementer's discretion: which Den type role each body row uses, how the `FoxLogo` is sized (currently a fixed 108 dp), and whether the entire block should be vertically centered in the viewport. The About screen is an identity surface — it is one of the two places in the app that renders the brand mark at scale (Welcome being the other) — so its typography and proportions matter more per-pixel than they do on the daily-path views.

#### 2.1.1 Type treatment across the About body (`FR-ABOUT-2.1`)

`FR-ABOUT-2.1` **The three body rows use three distinct roles from the Den type stack, chosen so the visual hierarchy reads identity → attribution → build-metadata, top to bottom.** No new font families are introduced; the Den stack (`DenType.serif` = Newsreader, `DenType.body` = Hanken Grotesk, `DenType.mono` = Spline Sans Mono) is exhaustive per `FR-DESIGN-1`.

- **Row 1 — "Produced by The Fox Works" — `DenType.serif`.** This row is the identity headline; it uses the same serif family the app reserves for titles (`DenType.h1` / `h1Compact`), rendered smaller than a screen title but larger than body copy — `22.sp`, `FontWeight.SemiBold`, `Den.ink`, `letterSpacing (-0.3).sp`. Concretely this matches the Material 3 `titleLarge` slot already wired into `Theme.kt` (serif 22.sp SemiBold), so no new `TextStyle` needs to be created — reuse the token.
- **Row 2 — "Implemented by Claude" — `DenType.body`.** Attribution copy; body register, 15.5.sp `FontWeight.Normal`, `Den.ink`. Matches the row 1 rhythm without competing with it visually.
- **Row 3 — "Version X.Y.Z" — `DenType.mono`.** Build metadata; `12.5.sp`, `letterSpacing 0.4.sp`, `Den.muted`. Consistent with `DenType.meta` used in headers for build/date metadata — signals this line is technical, not editorial.

`FR-ABOUT-2.1.1` **Contact Us link — `DenType.body`, `15.sp`, `FontWeight.SemiBold`, `Den.rust`.** Matches the current implementation; kept explicit so it does not drift with the surrounding size changes. Underline is not required (the Den palette + weight are enough to signal it as a link), but the tap target continues to meet `NFR-A11Y-1`'s ≥ 44 dp rule.

`FR-ABOUT-2.1.2` **Row alignment.** All three text rows remain centered horizontally (`textAlign = TextAlign.Center`) as they are today.

#### 2.1.2 `FoxLogo` sizes with the viewport (`FR-ABOUT-2.2`)

`FR-ABOUT-2.2` **`FoxLogo` is no longer hard-coded at 108 dp. It sizes proportionally to the viewport with a bounded ceiling so it is neither timid on a phone in portrait nor overwhelming on a wide/foldable canvas.** The sizing rule the implementer wires into `AboutScreen`:

```
logoSize = clamp(
    min(0.50 × viewportWidth, 0.45 × availableBodyHeight),
    96.dp,
    240.dp,
)
```

Where `viewportWidth` is the About screen's usable width (screen width minus horizontal padding) and `availableBodyHeight` is the vertical room between the bottom of the `RustHeader` and the bottom navigation-bar inset (i.e. the height available to the body `Column`, measured with `BoxWithConstraints` or an equivalent Compose primitive).

Concrete expectations on the three envelope cases:

- **Portrait phone (Pixel 8, ≈ 412 dp × 870 dp).** `0.50 × 412 = 206.dp` binds; height-ceiling does not. The roundel renders around 206 dp — "about half as wide as the screen" per the request — clearly the visual anchor of the screen but comfortably inside the horizontal margin.
- **Landscape phone / small foldable inner (≈ 700 dp × 380 dp).** Height binds: `0.45 × ≈ 230 dp available body = ≈ 104 dp`. The roundel shrinks to ~104 dp so the three text rows above and the Contact Us link below still fit without scrolling.
- **Portrait tablet / large foldable (≈ 900 dp × 1200 dp).** Half-width would be 450 dp; the clamp caps at 240 dp so the logo does not dominate a large canvas.

`FR-ABOUT-2.2.1` **Floor and ceiling are not negotiable.** The 96.dp floor keeps the mark legible on small screens and at very tall text scales; the 240.dp ceiling keeps it identity-sized, not billboard-sized, on wide displays.

`FR-ABOUT-2.2.2` **The `FoxLogo` composable itself is not modified.** Only the `size` parameter passed in from `AboutScreen` changes, using the formula above. The `ring` argument stays `Den.ink.a(0.06f)` as it is today.

#### 2.1.3 Vertical centering + no-scroll on default text scale (`FR-ABOUT-2.3` / `FR-ABOUT-2.4`)

`FR-ABOUT-2.3` **The About body content is vertically centered in the available body area on the default system text scale.** The current layout stacks the three text rows, then the logo, then Contact Us, from the top of the body with `Arrangement.spacedBy(20.dp)`. The new layout wraps that stack in a `Column` whose vertical arrangement is `Arrangement.Center` (or equivalently pads the top and bottom with equal `Spacer(Modifier.weight(1f))` bookends) so the whole block sits in the middle of the available body height rather than hugging the top under the header.

`FR-ABOUT-2.4` **The whole screen fits without vertical scrolling on the default system text scale in both portrait and landscape on a Pixel 8.** With the logo sized per `FR-ABOUT-2.2` and the vertical rhythm from `FR-ABOUT-2.5`, the body never overflows on default text scale. The `verticalScroll` modifier currently applied to the body `Column` is retained as an accessibility fallback — see `FR-ABOUT-2.4.1`.

`FR-ABOUT-2.4.1` **Scroll re-enables only when a large system text scale would otherwise clip content.** Behaviourally the body `Column` becomes scrollable when its natural content height exceeds the available body height (which happens at increased font-scale settings). This preserves `FR-ABOUT-1.6`'s a11y-fallback rule ("if the user increases system font size sufficiently to overflow, the screen becomes vertically scrollable — do not clip content"). Implementer's discretion on the mechanism (`verticalScroll` gated on a measurement, `LazyColumn` with a top/bottom spacer, or an equivalent).

`FR-ABOUT-2.5` **Vertical rhythm inside the centered block.**

- Between the three text rows: `Arrangement.spacedBy(6.dp)` as today — a tight identity block.
- Between the text block and the logo: `28.dp` gap.
- Between the logo and Contact Us: `24.dp` gap.
- Between Contact Us and the "no email app is available" hint (when shown): `10.dp` gap.

These numbers are exact tokens; the current code uses `Arrangement.spacedBy(20.dp)` uniformly, which reads as an unstructured stack. The new rhythm gives the identity block, the mark, and the affordance visibly distinct roles.

> **[DECISION] — Vertical centering is applied even when the content is very short.**
> An alternative was to top-anchor the block for consistency with Settings' scrolling body. But About is a leaf identity screen, not a list, and Settings is a scrolling list that will always begin from the top — the two are not analogous. Centering here is a deliberate identity choice.

> **[DECISION] — `serif` for row 1, not `body` or `mono`.**
> The request asks about "chosen font(s) and how they're used". The three-family Den stack gives us three obvious slots; using `serif` for the identity headline mirrors how the app treats screen titles (`h1` is serif), which visually says "this row *is* the identity". Using body for all three (the current implementation) reads as a leaflet, not a namebrand.

**Acceptance criteria**

1. Opening About shows, top-to-bottom in a **vertically centered** body block: row 1 in Den `serif` at 22.sp SemiBold, row 2 in Den `body` at 15.5.sp Normal, row 3 in Den `mono` at 12.5.sp with 0.4.sp letter-spacing (all centered horizontally); a `FoxLogo` sized per `FR-ABOUT-2.2`; and the "Contact Us" link in Den `body` at 15.sp SemiBold in `Den.rust`.
2. On a Pixel 8 in **portrait** at default system text scale, the `FoxLogo` renders at ≈ 206 dp (≈ 50% of viewport width), and the whole About body (three text rows + logo + Contact Us) is visible without scrolling.
3. On a Pixel 8 in **landscape** at default system text scale, the `FoxLogo` shrinks (height-ceiling binds) so that the whole About body remains visible without scrolling — nothing is clipped.
4. On a large canvas ≥ 900 dp wide (foldable inner / tablet), the `FoxLogo` is capped at 240 dp — it does not scale beyond that ceiling and does not dominate the viewport.
5. At an increased system font-scale (≥ 1.3× or wherever the natural content height exceeds the body area), the body becomes vertically scrollable and no content is clipped (`FR-ABOUT-1.6` fallback preserved).
6. The three rows and the Contact Us link continue to meet WCAG AA ≥ 4.5:1 contrast against the About background in light and dark themes (`NFR-A11Y-1`).
7. `FR-ABOUT-1.4` (version string sourced from `BuildConfig.VERSION_NAME`), `FR-ABOUT-1.5` (mailto intent), `FR-ABOUT-1.7` (`FoxLogo` reuse — no duplication), `FR-ABOUT-1.8` (menu-only entry), `FR-ABOUT-1.9` (read-only; nothing written), and `FR-ABOUT-1.10` (quiet voice on entry / exit) all continue to hold — none of them regresses.
8. No streak / points / badges / adherence surface appears anywhere on the About screen (`DM-NOT`).

**Out of scope for v2.4.0**

- **A dark-mode-specific type-role swap.** The three roles remain the same in both themes — only the colour tokens (`Den.ink` / `Den.muted` / `Den.rust`) change through the theme, which they do already.
- **A per-locale font override on the About screen.** RTL layout applies as it does elsewhere (`FR-2026-07-10-d` from v2.1.0); explicit per-locale font tuning is a separate concern.
- **Animating the `FoxLogo` on entry.** The screen remains quiet on entry / exit per `FR-ABOUT-1.10`.
- **Loosening the 96 / 240 dp clamp on `FoxLogo`.** These are load-bearing; changing them is a future requirement, not a v2.4.0 tuning knob.

### 2.2 Chrome palette consistency across top-level views (`FR-NAV-5`, refines `FR-NAV-1` chrome)

*Source: `FR-2026-07-11-b` (bullet 1). Refines `FR-NAV-1` chrome; deprecates `LayerHeader` on Habits / Directions / Journey.*

Today the seven top-level views split across two header styles:

- **`RustHeader`** (rust background, cream foreground) — Today, Planning, All Tasks, Backlog, Settings, About.
- **`LayerHeader`** (cream / surface background, ink foreground, per-view accent on the compass mark) — Habits, Directions, Journey.

The two styles were introduced in v2.0.0 to signal a "Direction / Reflection layer" separate from the daily-path "Action layer", but in practice — with the app grown to five tabs and the menu-driven reference views — the split reads as visual inconsistency, not as a meaningful layering. The user experience is that "some views look like a different app". Consistency wins.

`FR-NAV-5` **All top-level tab and reference views render their header with `RustHeader`.** Concretely:

- **Habits** (currently `LayerHeader(kicker = "HABITS · RHYTHM", title = "Habits", accent = Den.green, sub = "…", onMenu = …)`) migrates to `RustHeader(kicker = "HABITS · RHYTHM", title = "Habits", onMenu = …)`. The `sub` line ("Aim for the rate, not perfection…") moves out of the header — either into a body intro paragraph (a small `Text` item at the top of the list, in `Den.muted`, matching the existing intro-copy pattern used by Backlog's list) or into `metaLeft` if it fits on one line. Implementer's discretion, subject to `FR-NAV-5.2`.
- **Directions** (currently `LayerHeader(kicker = "DIRECTIONS · YOUR NORTH", title = "Directions", …, sub = "…", onMenu = …)`) migrates identically: `RustHeader` with the same title and kicker, `sub` moves into a body intro paragraph.
- **Journey** (currently `LayerHeader(kicker = "JOURNEY", title = "Journey", accent = Den.rust, …)`) migrates identically.

`FR-NAV-5.1` **`LayerHeader` is deprecated on the seven top-level views.** The composable itself may remain in `components/Headers.kt` for now (some downstream code paths may still reference it), but no top-level tab or reference view calls it after this milestone. Removing the composable outright is out of scope for v2.4.0; deletion happens once no call sites remain.

`FR-NAV-5.2` **The per-view accent (`Den.green` for Habits, `Den.rust` for Directions / Journey) is preserved through body chrome, not the header background.** Where the previous `LayerHeader` compass mark carried the accent colour, the accent now expresses itself in body group headers, chip fills, and progress bars — surfaces that already carry `Den.green` / `Den.rust` tokens today. The header background is uniformly `Den.rust` (`Den.cream` foreground).

`FR-NAV-5.3` **The `RustHeader` `compass = true` slot may be used on Habits / Directions / Journey to preserve the compass motif** (currently rendered by `LayerHeader`'s optional compass). If it is used, the compass tint continues to be `Den.cream` (matching how Today's `RustHeader` handles the motif); it does **not** carry the per-view accent, because a rust background with a green motif would read as decoration, not identity.

`FR-NAV-5.4` **The `kicker` line and the `title` on each migrated view are preserved verbatim** — "HABITS · RHYTHM" · "Habits"; "DIRECTIONS · YOUR NORTH" · "Directions"; "JOURNEY" · "Journey". Only the palette changes.

> **[DECISION] — Deprecate `LayerHeader` rather than repaint it in rust.**
> A minimal alternative was to change `LayerHeader`'s background from cream to rust in place and leave the call sites untouched. Rejected because `LayerHeader` also renders its title in `Den.ink` with a Material 3 `headlineLarge`-sized override (33.sp, half a size smaller than `RustHeader`'s 37.sp) — the two composables' typography stacks differ, and cross-migrating type + palette invites drift. Migrating the call sites to `RustHeader` outright is the cleaner path and also gives us the `FR-NAV-7` title-size normalisation for free.

**Acceptance criteria**

1. Habits, Directions, and Journey render a rust `RustHeader` with cream foreground — visually indistinguishable in palette from Today's header.
2. The kicker + title copy on all three migrated views is preserved verbatim; body-list group headers on those views still render in the per-view accent (green / rust) where they did previously.
3. `LayerHeader` has no call sites on Today, Planning, Habits, Directions, Journey, All Tasks, Backlog, Settings, or About after this milestone.
4. Any body-intro copy that previously lived in the `LayerHeader` `sub` slot (Habits' "Aim for the rate…" line; Directions' body-below-title copy) is preserved somewhere on the screen — either as a body intro paragraph or as a `metaLeft` line in the new `RustHeader`.
5. No streak / points / badges / adherence surface is introduced by the migration (`DM-NOT`).
6. Compass motif contrast on any header that opts into `compass = true` continues to meet `NFR-A11Y-1`.

**Out of scope for v2.4.0**

- **Deleting `LayerHeader` from `components/Headers.kt`.** Migration first; deletion can happen in a later increment once no call sites remain.
- **Introducing a third header style.** The Den palette continues to carry exactly one primary chrome — rust — going forward.

### 2.3 Navigation-affordance consistency — no dead-end views (`FR-NAV-6`, refines `FR-NAV-1` / `FR-NAV-3` / `FR-ABOUT-1.1`)

*Source: `FR-2026-07-11-b` (bullet 2). Refines `FR-NAV-1` (bottom-nav visibility), `FR-NAV-3` (hamburger placement), and `FR-ABOUT-1.1` (About left-slot affordance).*

Today the header-affordance and bottom-nav rules are:

| View | Bottom nav | Header top-right | Header top-left |
| --- | --- | --- | --- |
| Today | shown | hamburger | kicker |
| Planning | shown | hamburger | kicker |
| Habits | shown | hamburger | kicker |
| Directions | shown | hamburger | kicker |
| Journey | shown | hamburger | kicker |
| All Tasks | hidden | hamburger | kicker |
| Backlog | **hidden** | **decorative Moon icon (no menu)** | kicker |
| Settings | hidden | `×` (close) | kicker |
| About | hidden | *(empty)* | back chevron |

Two of these are dead-ends: **Backlog** has no menu button and no bottom nav, so the only way back is the system back gesture — a user who reached Backlog from the menu is effectively locked out of Today until they gesture back or restart. **All Tasks** has a hamburger but no bottom nav, so cross-tab navigation from there requires two taps (menu → tab) instead of one. And leaf destinations (Settings, About) use *different* close affordances (`×` vs. back chevron), which reads as accidental rather than intentional.

`FR-NAV-6` **Every view in the app falls into one of two navigation-chrome classes; the choice is deterministic per view, and no view sits outside the classification.**

- **Class A — daily-path and reference views.** Today, Planning, Habits, Directions, Journey, **All Tasks, Backlog.** All show the `DenBottomNav` at the bottom (`FR-NAV-6.1`) and a hamburger in the header's top-right slot (`FR-NAV-6.2`). Back gesture behaves per platform default.
- **Class B — leaf destinations.** Settings, About. **Both** show a **close (`×`)** in the header's top-right slot, which pops the destination and returns to the underlying view (`FR-NAV-6.3`). Neither shows a bottom nav (they are leaves, not tabs), and neither shows a hamburger (the parent view carries it).

`FR-NAV-6.1` **`DenBottomNav` is rendered on All Tasks and Backlog with no active tab highlighted.** The `active` parameter is passed as `null`-equivalent — the bar renders every tab in its inactive style; no tab shows the rust pill. Tapping any tab navigates to that tab and pops back to the corresponding root destination (the same `goTab` behaviour Today uses). Implementer's discretion on whether to extend `DenBottomNav`'s signature to accept `active: Tab?` or to introduce a sentinel; the visible behaviour is the requirement.

`FR-NAV-6.2` **The hamburger on All Tasks and Backlog uses the same `HeaderMenuButton` composable that Today / Planning / Habits / Directions / Journey already use, in the top-right slot.** On All Tasks it replaces the current explicit `HeaderMenuButton(onClick = …)` wiring (no change to the visible affordance). On Backlog it **replaces the decorative `TzIcons.Moon` currently occupying the `right` slot** — the moon glyph was identity decoration, not a control, and its presence there is why the view reads as a dead-end. Backlog gains `onMenu = { menu = true }` and drops the decorative right slot. The `AppMenuSheet` opened from Backlog's hamburger contains the same four rows (`FR-NAV-4`); the row for "Backlog" is omitted from the sheet when Backlog is the underlying view (implementer's discretion — either omit the row when the current route is Backlog, or leave it and let a re-tap noop, the latter being simpler).

`FR-NAV-6.3` **Settings and About use a `×` (close) affordance in the header's top-right slot** — the same treatment Settings already uses. About's **back chevron in the left slot is removed**; the header's top-left slot on About reverts to the standard kicker line ("TZAFON" in Den mono, matching Settings), and the top-right slot carries the `×`. Tapping `×` pops the destination back to whichever view opened the menu that led to About / Settings. This deletes `FR-ABOUT-1.1`'s "back chevron in the left slot dismisses the About destination" clause and replaces it with a `×` in the right slot; the semantic behaviour (return to the underlying view) is unchanged.

`FR-NAV-6.4` **The `AppMenuSheet` sheet contents (`FR-NAV-1`, refined by `FR-NAV-4`) are unchanged.** The sheet still opens with the same four rows in the same order — All Tasks · Backlog · Settings · About — from any Class-A view's hamburger.

`FR-NAV-6.5` **The five-tab primary structure (`FR-NAV-1`) is preserved.** All Tasks and Backlog remain reference views reached from the menu; they do **not** become bottom-nav tabs. Rendering the bottom nav on those two views is a wayfinding aid, not a promotion — the visible tab set continues to be the same five (Today · Planning · Habits · Directions · Journey).

> **[DECISION] — Bottom nav on All Tasks / Backlog renders with no active tab, not with the "closest" tab highlighted.**
> An alternative was to highlight Today (the default) or the tab the user came from. Rejected: those views are not tabs, and pretending one is highlighted would either mislead the user ("I'm on Today?") or leak backstack state into the header UI. Rendering all five inactive is honest — the bar is a wayfinder, not a status indicator.

> **[DECISION] — Leaf-destination close is `×`, not back chevron.**
> The user's suggestion explicitly names `×`. Consistent with Settings, which has used `×` since M9. About migrates to match.

**Acceptance criteria**

1. From Backlog, tapping any bottom-nav tab navigates to that tab (Today / Planning / Habits / Directions / Journey); the user is never dead-ended on Backlog.
2. From All Tasks, tapping any bottom-nav tab navigates to that tab; the bottom-nav highlight on All Tasks and Backlog shows no active tab.
3. Backlog's header shows a hamburger in the top-right slot; tapping it opens `AppMenuSheet` with the four rows from `FR-NAV-4`. The decorative Moon glyph is no longer present in the header right slot.
4. All Tasks' header continues to show a hamburger in the top-right slot (unchanged behaviour, cleaned wiring via `HeaderMenuButton`).
5. Settings and About both show a `×` (close) affordance in the header's top-right slot; tapping it returns to the underlying view. About no longer shows a back chevron in the left slot; the left slot renders the "TZAFON" kicker consistent with Settings.
6. TalkBack announces the `×` as "Close" on both Settings and About with a distinct `contentDescription`; the hamburger on All Tasks / Backlog announces as "Menu" consistent with the other Class-A views (`NFR-A11Y-1`).
7. No regressions to `AppMenuSheet` contents (four rows: All Tasks · Backlog · Settings · About) or `FR-NAV-1`'s five-tab structure.
8. `DM-NOT` audit clean — no gamification surface introduced.

**Out of scope for v2.4.0**

- **Promoting All Tasks or Backlog to primary tabs.** The five-tab structure is locked.
- **A "close all screens" gesture or a home shortcut in the bottom nav.** The bottom nav's contract remains "tap → go to that tab".
- **Suppressing the `AppMenuSheet` row for the current view.** If the user is on Backlog and taps hamburger → Backlog row, the sheet closes and the user stays on Backlog — acceptable v2.4.0 behaviour; a smarter suppression can come later.

### 2.4 Screen-title size + Planning header restructure (`FR-NAV-7`, refines `FR-PLAN-1`)

*Source: `FR-2026-07-11-b` (bullet 3). Refines `FR-PLAN-1` (Planning header) and adjusts About / Settings / Backlog / All Tasks title sizing.*

Today's `RustHeader` supports a `compact = true` opt-in that renders the title with `DenType.h1Compact` (28.sp) instead of `DenType.h1` (37.sp), and shrinks the surrounding padding. Five screens use it: Planning, Settings, About, Backlog, All Tasks. Two screens do not: Today, plus the Journey / Directions / Habits set (currently on `LayerHeader`, which uses a 33.sp Material 3 `headlineLarge` override — a third size).

The result is that "Today" reads at 37.sp, "Habits" at 33.sp, and "Planning" at 28.sp — three sizes across the header set, chosen for no reason a user can perceive. Combined with `FR-NAV-5`'s move to a single header palette, the title size should also be one number.

`FR-NAV-7` **The `RustHeader` title is uniformly rendered at `DenType.h1` (37.sp SemiBold, serif). The `compact` parameter is retired.**

`FR-NAV-7.1` **`RustHeader`'s `compact: Boolean = false` parameter is removed** from the composable signature (or, if kept for source-compat, is hard-coded to `false` internally and marked `@Deprecated`). All call sites that previously passed `compact = true` (Planning, Settings, About, Backlog, All Tasks) drop the argument. The header's vertical padding uses the non-compact values on all views.

`FR-NAV-7.2` **Planning's header restructures so the current date replaces "WHAT'S ON THE TABLE".** The change on `PlanningScreen`:

- `kicker` becomes the current date — `Dates.fmtDate(state.today, state.today)` (the string previously fed into `metaLeft`). No `"WHAT'S ON THE TABLE"` line is rendered.
- `metaLeft` is dropped from the `RustHeader` call (the date has moved into the kicker slot; not repeated).
- `metaRight` — the "N undated" count — is retained in its current slot below the title. This keeps the "undated" count as ambient information without inflating the header.
- `bottomContent` (the range presets row) is unchanged.
- `compact` is dropped, so the title "Planning" renders at 37.sp, matching Today.

`FR-NAV-7.3` **Settings and About keep their `kicker = "TZAFON"` line** (no source of a per-screen dynamic kicker like Planning's date), rendered at the same mono-caps style as elsewhere. Their titles ("Settings", "About") now render at 37.sp instead of 28.sp; the surrounding padding scales accordingly. Settings' scrollable body absorbs the extra header height; About's centered body (`FR-ABOUT-2.3`) recomputes its centering with the larger header. The About-screen no-scroll rule (`FR-ABOUT-2.4`) continues to hold at default text scale — the extra ~30 dp of header height is small enough that with the `FoxLogo` sized per `FR-ABOUT-2.2` the body still fits.

`FR-NAV-7.4` **All Tasks and Backlog titles ("All Tasks", "Backlog") render at 37.sp.** All Tasks' `bottomContent` (search input + segmented control chips) is preserved; the header grows vertically but stays consistent with Today's rhythm. Backlog's meta line ("Parked — not scheduled" / "N items") is preserved.

`FR-NAV-7.5` **The migrated Habits / Directions / Journey views (`FR-NAV-5`) render their titles at 37.sp by consequence** — they now use `RustHeader` without `compact`, so they land on the same value automatically. No dedicated action needed.

`FR-NAV-7.6` **`DenType.h1Compact` is not removed from `Type.kt`.** Downstream body-copy or card-header uses may still reference it; only the `RustHeader.compact` opt-in goes away. Removal of `h1Compact` from the theme file is out of scope for v2.4.0.

> **[DECISION] — Planning's kicker slot carries the date, not a static "TODAY IS" prefix.**
> The user's phrasing is "Put the date where the 'WHAT'S ON THE TABLE' text is now". The kicker slot renders in Den mono at 11.sp with caps letter-spacing — a formatted date like `MON, JUL 11 2026` reads well in that slot without a prefix. Adding a "TODAY IS" prefix would double the kicker line's meaning without adding information. If the formatted date's punctuation reads oddly in the caps kicker style, the implementer may format it in `Dates.fmtDate` with title-case punctuation intact (the kicker's caps transform continues to apply).

> **[DECISION] — Settings / About / Backlog / All Tasks keep their existing kicker copy.**
> Only Planning has a genuinely dynamic kicker candidate (the date). Retiring the other views' kicker copy would be a separate design change; the request is title-size normalisation and the specific Planning restructure, not a whole-app kicker rewrite.
