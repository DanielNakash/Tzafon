**Builds on:** **Tzafon v2.2.0** (released). This document is an **increment** — it does not restate the v2.0.0 / v2.1.0 / v2.2.0 spec, only the requirements added or refined for v2.3.0. Prior requirements remain in force except where a section below explicitly refines one.

## 1. Scope of v2.3.0

v2.3.0 is a **single-surface identity increment** on top of a shipped v2.2.0. One request, one new screen, one new menu row, no new object types, no schema migrations (see §4 — Data model deltas below, which is intentionally empty). All locked decisions from v2.0.0 continue to hold — in particular the whole of `DM-NOT` (no streaks / points / badges / adherence %), the ≤3 active themes cap, and the `FR-NAV-1` five-tab primary structure.

The single requirement:

- **`FR-ABOUT-1`** introduces a new **About** screen reachable from the header menu that identifies the app's producer ("The Fox Works"), its implementer ("Claude"), and its running version, re-uses the `FoxLogo` brand mark as identity (`FR-NAV-3.4` explicitly preserved the composable for exactly this kind of surface), and offers a one-tap **Contact Us** mailto affordance. `FR-NAV-4` adds a fourth row to `AppMenuSheet` — the menu already introduced by `FR-NAV-1` and re-triggered by `FR-NAV-3`'s hamburger — routing to the new About screen.

The change is a UI-surface addition against existing header chrome, existing menu sheet, and the existing `FoxLogo` composable. It closes the "who made this, and how do I reach them?" discoverability gap that surfaced only after v2.2.0's hamburger swap made the brand mark stop functioning as a control.

## 2. Functional requirements

### 2.1 About screen — producer, implementer, version, contact (`FR-ABOUT-1`, `FR-NAV-4`)

*Source: `FR-2026-07-10-h`. Adds `FR-ABOUT-*`; refines `FR-NAV-1` (menu contents).*

Today, `AppMenuSheet` ("Around the den") exposes three rows — All Tasks · Backlog · Settings (`FR-NAV-1`, unchanged by `FR-NAV-3`). There is no in-app surface that identifies the producer or the implementer, and no discoverable channel for the user to reach the producer. The running version is present in `BuildConfig.VERSION_NAME` but is never displayed. v2.2.0's `FR-NAV-3.4` explicitly preserved the `FoxLogo` composable for identity uses outside the menu trigger — the About screen is one such use.

#### 2.1.1 Menu entry (`FR-NAV-4`, refines `FR-NAV-1`)

`FR-NAV-4` **`AppMenuSheet` gains a fourth row, "About", that routes to the new About screen.** The row appears **after** the existing Settings row so the daily-path ordering (reference views first, then app-scoped rows) is preserved: All Tasks · Backlog · Settings · About. Icon and subtitle follow the sheet's existing row conventions (a `TzIcons` glyph in the Den palette, a short one-line subtitle in the sheet's muted body voice).

`FR-NAV-4.1` **Subtitle voice.** The row's subtitle is a short, Den-voiced descriptor (e.g. "Producer, implementer, contact") — declarative, no marketing copy, no exclamation marks. Consistent with the existing rows' `The complete, searchable index` / `Someday / maybe — parked, not scheduled` / `Week start, reminders, account` register.

`FR-NAV-4.2` **Icon.** The row uses a `TzIcons` glyph rendered in the Den palette at the same `17.dp` size the other menu rows use, with contrast against the sheet background meeting `NFR-A11Y-1`. The specific glyph is at the implementer's discretion within the `TzIcons` family (e.g. an information glyph or the compass mark), provided it is visually distinct from the three glyphs already in the sheet (Search / Moon / Bell). Do **not** use `FoxLogo` in the menu row — the roundel remains reserved for identity surfaces per `FR-NAV-3.4`, not as a menu row icon.

`FR-NAV-4.3` **Placement and ordering are fixed.** About sits at position 4 — after Settings. The row is always present (unlike `onBacklog` / `onSettings` which are nullable in the current `AppMenuSheet` signature); About is unconditionally rendered because it has no state precondition.

`FR-NAV-4.4` **The sheet's voice and structure are otherwise unchanged.** Title stays "Around the den", the three existing rows keep their titles/subtitles/icons/order, and no behavioural change occurs to how the sheet opens or dismisses (`FR-NAV-3`'s hamburger trigger remains the sole opener on Today / Planning / All Tasks).

#### 2.1.2 About screen — layout and contents (`FR-ABOUT-1`)

`FR-ABOUT-1` **The About screen is a standalone destination reached from `AppMenuSheet` → About that identifies the producer, the implementer, the running version, and offers a single mailto contact affordance.** It is a **reference view**, not a daily-path view — the same tier as Settings.

`FR-ABOUT-1.1` **Header.** The screen mounts `RustHeader` with the title **"About"**. A back chevron in the left slot dismisses the About destination and returns the user to whichever screen opened `AppMenuSheet`. The right slot is empty — the About screen is a leaf, so no menu-affordance re-trigger from within About (the hamburger is not repeated here). The header retains its Den styling (`Den.rust` background, `Den.cream` foreground) exactly as on Settings.

`FR-ABOUT-1.2` **Body content, in order:**

1. A short text block, one line per row, in the body's default Den voice:
   - Row 1: **"Produced by The Fox Works"**
   - Row 2: **"Implemented by Claude"**
   - Row 3: **"Version X.Y.Z"** where `X.Y.Z` is the running `versionName` from `BuildConfig.VERSION_NAME` (see `FR-ABOUT-1.4`).
2. The `FoxLogo` composable rendered at a size appropriate to the screen (a comfortable identity size, larger than the header roundel but not dominating the viewport — implementer's discretion, subject to `FR-ABOUT-1.6`).
3. **Under the logo**, a **Contact Us** link that opens an email intent addressed to **`thefoxworksdotnet@gmail.com`** (see `FR-ABOUT-1.5`).

No other content — no changelog, no credits list, no third-party licence viewer, no support links. The screen is intentionally spare.

`FR-ABOUT-1.3` **Text register.** The three text rows use plain declarative sentences. There is no marketing copy ("Made with love"), no achievement language, no streak / points / badges / adherence surface (`DM-NOT`, `DEC-2/3/4`) — About is inert display and must remain inert.

`FR-ABOUT-1.4` **Version source is `BuildConfig.VERSION_NAME`.** The screen reads the version at render time from the generated `BuildConfig`, so the string always reflects the shipped build — no hard-coded literal, no separately maintained constant. The string is rendered as `Version <versionName>` (e.g. `Version 2.3.0`), matching the pattern the user specified. The `versionCode` is not surfaced (not requested; not user-facing information).

`FR-ABOUT-1.5` **Contact Us affordance opens an email intent.**

- The link's display text is exactly **"Contact Us"** (not the email address; the address is the target, not the label).
- Activation launches `Intent(Intent.ACTION_SENDTO, Uri.parse("mailto:thefoxworksdotnet@gmail.com"))`. Using `ACTION_SENDTO` with the `mailto:` scheme ensures only true email handlers appear in the chooser — a plain `ACTION_VIEW` or `ACTION_SEND` would surface every social/share target on the device.
- No subject or body prefill in v2.3.0 — the user composes freely. (See out-of-scope note below.)
- If no email handler is installed on the device, the intent will fail to resolve. The implementation must handle the `ActivityNotFoundException` gracefully — a short in-app snackbar/inline hint ("No email app is available") is sufficient. Do **not** crash, and do **not** fall back to copying the address to the clipboard silently (surprising side-effect without user consent).
- The tap target is at least `44dp` per `NFR-A11Y-1` and is clearly styled as a link (Den palette, distinguishable from body text — implementer's choice within Den tokens).

`FR-ABOUT-1.6` **Layout.** Vertical stack, centered horizontally, comfortable vertical rhythm between the text block, the logo, and the Contact Us link. On a Pixel 8 (`emulator -avd Pixel_8`) in both portrait and landscape, all three elements are visible without scrolling on the default text scale; if the user increases system font size sufficiently to overflow, the screen becomes vertically scrollable (do not clip content). Padding follows the Den convention used by Settings.

`FR-ABOUT-1.7` **`FoxLogo` reuse — no duplication.** The About screen renders the existing `FoxLogo` composable. Do not fork the drawable, do not introduce a second identity mark. This is the identity surface `FR-NAV-3.4` explicitly preserved the composable for.

`FR-ABOUT-1.8` **Navigation entry point is menu-only.** About is reachable **only** via `AppMenuSheet` → About. It is not added to the bottom-nav (`FR-NAV-1` remains a five-tab primary structure), it is not deep-linked from any other surface in v2.3.0, and it is not exposed via a header affordance on any other screen. A user reaches About by tapping the hamburger (`FR-NAV-3`) → About row (`FR-NAV-4`).

`FR-ABOUT-1.9` **Save / write behaviour — none.** About renders read-only content sourced from `BuildConfig` and a static string block. It writes nothing to the repositories, it consumes no `SettingsRepository` state, it does not touch Room. Rotation preserves scroll position via the standard Compose scroll state.

`FR-ABOUT-1.10` **Quiet voice on entry and exit.** Entering or leaving About triggers no toast, snackbar, or transient copy. Consistent with the Den aesthetic and `DM-NOT`, this is a plain reference view.

> **[DECISION] — About is a full destination, not a bottom-sheet.**
> Two alternatives were considered: (a) render About in a bottom-sheet dialog opened from the menu (dismissible in place), (b) push About as a full destination on the nav backstack (this requirement). (a) puts a brand mark and multi-row content in a sheet that reads as a transient control, and it competes with `AppMenuSheet` opening from underneath; (b) matches how Settings is reached and behaves. The user's request specifies "Accessing the About section shall be from the hamburger menu" — reachable, not embedded in the menu — so About is a peer of Settings, not a sub-sheet of the menu sheet.

> **[DECISION] — Email address is `thefoxworksdotnet@gmail.com` verbatim.**
> The request specifies `thefoxworksdotnet@gmail.com` (the domain `thefoxworks.net` transliterated into the local part, hosted on Gmail). This is used **exactly as given**; no normalisation, no attempted `hello@thefoxworks.net` "correction". If the owner later wants a different address, updating this requirement and the mailto target is a one-line edit.

**Acceptance criteria**

1. Opening `AppMenuSheet` (via `FR-NAV-3`'s hamburger on Today / Planning / All Tasks) shows **four** rows in order: All Tasks · Backlog · Settings · **About**, each with a distinct `TzIcons` glyph and a short Den-voiced subtitle.
2. Tapping the **About** row closes the sheet and navigates to a new About destination whose header (`RustHeader`) reads **"About"** with a back chevron in the left slot; back chevron returns to the underlying screen.
3. The About screen body contains, top-to-bottom: (a) three text rows — **"Produced by The Fox Works"**, **"Implemented by Claude"**, **"Version X.Y.Z"** — where `X.Y.Z` matches `BuildConfig.VERSION_NAME` at run time; (b) the `FoxLogo` composable rendered at an identity-appropriate size; (c) a **Contact Us** link.
4. Tapping **Contact Us** launches an `Intent.ACTION_SENDTO` with URI `mailto:thefoxworksdotnet@gmail.com` and no prefilled subject or body. If no email handler is installed, a short inline hint appears and the app does not crash.
5. `FoxLogo` renders on the About screen unchanged from its other identity uses (Welcome / onboarding). The `AppMenuSheet` About row does **not** use `FoxLogo` as its icon — a distinct `TzIcons` glyph is used.
6. No streak / points / badges / adherence surface appears anywhere in the flow (`DM-NOT`, `DEC-2/3/4`).
7. The About screen writes nothing to Room, mutates no repository, and produces no toast/snackbar on entry or exit.
8. TalkBack announces the About menu row with a distinct `contentDescription`; the Contact Us link announces as a link with target information adequate for a screen-reader user to know it opens an email compose; hit targets meet `NFR-A11Y-1` sizing (≥ 44dp). Text contrast on the About body against the screen background meets **WCAG AA ≥ 4.5:1** in both light and dark themes; the Contact Us link satisfies **≥ 4.5:1** as well.
9. Rotating the device on the About screen preserves scroll position and content is not clipped at increased system font sizes (the screen becomes vertically scrollable when necessary).

**Out of scope for v2.3.0**

- **A changelog / release-notes viewer on the About screen.** `CHANGELOG.md` lives in the repo; surfacing it in-app is a separate discoverability question and not requested.
- **A third-party licence viewer (OSS attributions screen).** Not requested; can be added later if the dependency footprint grows.
- **Prefilled subject / body on the Contact Us intent.** The request specifies only the recipient. A future request may add a versioned `Subject: Tzafon vX.Y.Z feedback` or diagnostic-context body, but not in v2.3.0.
- **A copy-address-to-clipboard fallback.** Explicitly rejected per `FR-ABOUT-1.5`; a graceful in-app hint is the fallback.
- **Additional entry points to About** (e.g. long-press on `FoxLogo` elsewhere, a Directions shortcut, a Settings sub-row). About is reachable via the menu only per `FR-ABOUT-1.8`.
- **A dark-mode-specific alternate logo.** `FoxLogo` already renders correctly in both themes per the existing composable; no dedicated dark variant is introduced here.
- **Localisation of the About body text beyond RTL layout support.** RTL layout (`FR-2026-07-10-d` from v2.1.0) applies as it does elsewhere; explicit translation of the English strings is a separate concern.

## 3. Non-functional requirements

No new NFRs in v2.3.0. `FR-ABOUT-1` **strengthens conformance** with existing `NFR-A11Y-1`:

- The About screen introduces one new interactive element (Contact Us link) with distinct content description and ≥ 44dp hit target.
- The new menu row (`FR-NAV-4`) introduces one new interactive element (About row) with distinct content description alongside the existing three rows.
- Body text and link contrast against the About screen background meet WCAG AA ≥ 4.5:1 in both light and dark themes.
- Intent failure (`ActivityNotFoundException`) is handled without a crash per `NFR-OFFLINE-1`'s spirit — degrading gracefully when a device capability is missing.

All other `NFR-*` from v2.0.0 / v2.1.0 / v2.2.0 continue to apply unchanged.

## 5. Acceptance criteria for "v2.3.0 is done"

v2.3.0 is complete when:

1. `FR-ABOUT-1` and `FR-NAV-4` pass their acceptance criteria in §2 on the emulator.
2. All v2.0.0 / v2.1.0 / v2.2.0 acceptance criteria still pass — nothing regressed, in particular:
   - `DM-NOT` (no gamification anywhere), including on the About screen and in the menu-row subtitle;
   - `FR-NAV-1`'s five-tab primary structure — About is menu-only, not bottom-nav;
   - `FR-NAV-3`'s hamburger remains the sole menu trigger on Today / Planning / All Tasks; About does not re-mount the hamburger inside itself;
   - `AppMenuSheet` title, existing three rows, and their subtitles/icons/order are unchanged;
   - `FoxLogo` continues to render on Welcome / onboarding and any other identity surface (v2.2.0's `FR-NAV-3.4` preservation guarantee).
3. Automated tests cover:
   - a Compose UI test that `AppMenuSheet` renders four rows in order (All Tasks · Backlog · Settings · About) with distinct content descriptions;
   - a Compose UI test that tapping the About row navigates to the About destination and dismisses the sheet;
   - a Compose UI test asserting the About screen renders the three text rows exactly as specified in `FR-ABOUT-1.2`, and that the version row string ends with the current `BuildConfig.VERSION_NAME`;
   - a Compose UI test asserting `FoxLogo` is present on the About screen;
   - a unit test (or Compose test with an intent-capture rule) that tapping **Contact Us** dispatches an `ACTION_SENDTO` intent with URI exactly `mailto:thefoxworksdotnet@gmail.com`;
   - a Compose UI test that when the SendTo intent fails to resolve, the app does not crash and an inline "no email app" hint appears.
4. Debug build installs and launches; no logcat `FATAL` / `AndroidRuntime` lines introduced. Body text and Contact Us link contrast against the About screen background meet **WCAG AA ≥ 4.5:1** in light and dark themes (`NFR-A11Y-1`).

## 6. Milestones

Ordered plan for the builder. Each milestone ends with a green test suite, a headless install-and-screenshot verification, and a git commit citing the milestone + requirement codes.

### M1 — About screen + menu wiring (`FR-ABOUT-1`, `FR-NAV-4`, refines `FR-NAV-1`)

- **Scope:**
  1. Add an `AboutScreen` composable (new file under `ui/about/`) that mounts `RustHeader` with title `"About"` and a back chevron, then renders the three-line body text, the `FoxLogo` at an identity-appropriate size, and a **Contact Us** link styled per Den tokens.
  2. Wire the Contact Us link to launch `Intent(Intent.ACTION_SENDTO, Uri.parse("mailto:thefoxworksdotnet@gmail.com"))`. Wrap the launch in a `try/catch` on `ActivityNotFoundException` that surfaces a short inline hint ("No email app is available") — no crash, no silent clipboard fallback.
  3. Read the version string from `BuildConfig.VERSION_NAME` at render time; render as `Version <versionName>`.
  4. Add a fourth row — **About** — to `AppMenuSheet` in `ui/nav/BottomNav.kt`, positioned **after** the existing Settings row. Icon: a distinct `TzIcons` glyph (not `FoxLogo`). Subtitle: a Den-voiced descriptor (e.g. "Producer, implementer, contact"). The row is unconditionally rendered (unlike the nullable `onBacklog` / `onSettings` params); wire an `onAbout: () -> Unit` callback that closes the sheet and navigates to the About destination.
  5. Register the About destination in the nav graph as a peer of Settings — reachable only from the menu. Threading the `onAbout` callback through the same Today / Planning / All Tasks screens that already thread `onBacklog` and `onSettings` keeps the change local and mirrors existing patterns.
  6. Do not modify `FoxLogo` itself. Do not remove or re-order the three existing menu rows. Do not add About to the bottom nav.
- **Why single-milestone:** the request describes one coherent surface — a menu entry that opens a screen. The menu row is meaningless without the destination it opens, and the destination is undiscoverable without the menu row. Splitting them into two milestones would ship a half-wired feature between commits.
- **Verify:**
  - Compose UI tests per §5.3 (menu row list, About row navigation, three body-text rows, version string, `FoxLogo` presence, `ACTION_SENDTO` intent target, no-email-handler graceful hint).
  - `cd android && ./gradlew testDebugUnitTest` and the Compose UI suite green.
  - Headless install + launch: navigate hamburger → About; capture screenshots in light and dark themes.
  - Contrast check on the About body text and Contact Us link against the screen background: WCAG AA ≥ 4.5:1 in both themes (`NFR-A11Y-1`, §5.4).
  - `adb logcat -d | grep -iE 'AndroidRuntime|FATAL'` clean after opening and closing About repeatedly and after the no-email-handler path is exercised via `adb shell pm disable-user` on a mail package (or an equivalent way to force the intent to fail).
- **Done when:** M1 tests pass; §5 acceptance criteria for `FR-ABOUT-1` and `FR-NAV-4` all pass; `DM-NOT` audit shows no gamification surface added on the About screen or in the menu row; commit references `FR-ABOUT-1` and `FR-NAV-4` (and `FR-NAV-1`, `FR-NAV-3.4`) and cross-references source request `FR-2026-07-10-h`.
